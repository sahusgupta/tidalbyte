# Command review

The atlas sends a typed request to `POST /api/v1/ai/interpret` with the current versioned scenario. The response is a proposal. The bar validates the response envelope, Houston region, scenario version, arguments and enabled controls. Confirm repeats validation against the latest scenario before dispatching a command once.

The bar accepts only actions enabled by its host: Houston recentering, a supported preset, a conditional county evaluation, explicit overlay visibility, the evidence view, and illustrative planning commands when `canPlan` is enabled. The published backend proposes county-overlay visibility only; its `{visible}` arguments map to `outages`. Unsupported, stale or unavailable commands leave the map untouched.

Planning reuses `COMPARE_INTERVENTION` with an exact `intent` union: `compare`, `prioritize_hospitals`, `assume_blocked`, `explain`, or `resources`. Resources also requires integer `totalBudget` (0–200) and `crewCapacity` (0–6). Every planning proposal requires confirmation. The host sets `selectedPlanningEdge` for an assumed blockage; the bar captures that selection before interpretation and checks it again at confirmation. The host must include its planning edit revision in the scenario version so resource, priority and assumption changes also invalidate stale proposals. Confirmation describes clinic priority 10/shelter priority capped 3 for both agencies, or the exact joint budget/crew limit. Explanations open the computed Nash bargaining explanation; the assistant does not invent allocations or scores.

Keyless examples include “Compare plans”, “Prioritize hospitals”, “Assume this link is blocked”, “Explain the plan”, and “Set joint budget 120 and crew limit 3”. The exact legacy illustrative-link phrase still returns its clarification.

Voice uses microphone permission requested by the Record button. Stop posts the recording as multipart field `audio` for transcription. Cancel discards it. Capture is limited to 20 seconds and 4 MiB, matching the server. The transcript remains editable and requires a separate **Propose** action before interpretation. No transcription automatically requests or executes a command. An empty transcript leaves typed controls available.

Provider and offline warnings remain visible. When ElevenLabs is unavailable, the backend can return fixed sample text unrelated to the recording; the UI labels that sample before review. Interpretation warnings distinguish Gemini from the built-in offline interpreter. The published county-only `{visible}` overlay command maps only to the enabled `outages` layer; other overlay commands require explicit allowlisted IDs. The interpreter request allows 12 seconds for the server's 8-second provider deadline, and transcription allows 20 seconds for its 12-second deadline. Provider secrets belong on the server.

The named `SpeakPlanSummary` component accepts the planner’s deterministic `text` and optional test `fetcher`/`baseUrl`. Its explicit action posts the text verbatim to `/api/v1/voice/speak`, then exposes native audio playback controls. It aborts requests and clears audio when that text changes, and revokes object URLs on cleanup. Narration requires server-only `ELEVENLABS_API_KEY` and `ELEVENLABS_VOICE_ID`; unavailable narration returns 503 with no fake audio. Transcription and narration share the provider request budget. Text is limited to 2,000 characters and output to 4 MiB. The provider only voices the computed summary; it does not generate planning results.
