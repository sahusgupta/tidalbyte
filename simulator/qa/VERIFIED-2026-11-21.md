# Four-region browser verification — 2026-11-21

All eight cases passed against the integrated local atlas (:5173), simulator (:5174)
and prepared-region API (:8001). Each case entered through the atlas Study menu →
Earth → named zone, matched the simulator's accessible region name and API endpoint,
and rendered without a fallback notice. No API responses or model outputs were mocked.

Desktop used 1440×900 CSS pixels; mobile used 390×844 with emulated touch at DPR 1.
This was **not a physical-phone test**. All eight reported hardware ANGLE on AMD
Radeon 890M / Direct3D11. Remote provider requests were blocked, leaving bundled
imagery, workers and fonts available.

Each row changed the model's returned depth arrays during storm playback, then used
its reviewed shower scenario, ambulance and clicked/tapped road pin. The returned
route was non-blocked, had multiple vertices, exceeded 100 m, and appeared with From/To
information. Every gesture generated exactly one pin request.

Fingerprints hash the returned road/building depth arrays, not merely a UI time
label. Prefixes above show 12 hex characters; full hashes, requests, compact response
summaries and 16 opening/pin captures were written outside Git to
`TEMP/earthlab-atlas-qa/four-zones-final-20261121`. Running the harness regenerates
its own evidence folder. These checks do not independently validate prediction
accuracy: the API identifies its model as an XGBoost surrogate of a process-based
flood simulator. They establish software behavior, not current road safety.

All four reviewed destinations are actual catalogued healthcare POIs, **not proxies**.
Their API notes identify Overture Places hospital/emergency-department records.
Operator identity/address references and exact destination IDs are in
[verified-pins.json](verified-pins.json). Address checks do not verify entrances,
current operating status, suitability or safe access.

## Repaired regression

Before the native ground-pin fix 842b2a6, Meyerland desktop and emulated touch both
rendered and changed model results but failed to emit a successful pin. Native DOM
tracing showed pointer-down/up/click reaching `#view-default-view`; an independent
standalone mouse reproduction also emitted no simulation request. The object-picking
path was unsuitable as the sole ground-pin input path. Ground pins now unproject a
native primary gesture through the active public Deck viewport, while retaining
hover/tooltips and excluding drags, multiple pointers, controls and context menus.
The all-eight run above passed after that fix; the earlier failure is retained here.

## Commands and limits

`npm ci --ignore-scripts`, `node --check verify-zones.mjs` and `npm run verify`
were run from `simulator/qa`. Frontend typecheck and production build passed.
A negative test with a deliberately missing reviewed hospital ID failed explicitly
before browser launch, confirming that no destination is silently substituted.
Prepared region files/models remain local runtime dependencies; no raw geodata,
weights, screenshots or response arrays are committed by this QA package.
